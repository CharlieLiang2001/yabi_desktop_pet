# 亚比桌宠4.3.2 · 连续注视验证

验证日期：2026-09-14。环境：本机Windows 11 x64、系统.NET Framework/WPF。

## 结论

已产出可运行的小幅连续注视体验版：站立和坐姿都可随鼠标连续响应，支持上下左右及斜向目标，无驻留、方向冷却或互动面板门槛。它不是独立眼球或真实大角度侧脸模型；这些素材能力仍未完成。空闲工作集也尚未达到之前150 MiB的目标。

## 验证证据

- 最终构建自检PASS、0失败：保留设置迁移、养成、提醒、动作目录及队列检查，新增连续控制器和网格约束测试。
- 控制器验证首次采样即响应、眼部领先头颈、连续换向、镜像、回正、非法输入保护，以及20/30/60/144Hz时间步长一致性。
- 站立/坐姿共162组极端参数组合进行网格局部方向采样检查；下半身采样点固定，未发现局部翻转。有限采样不是所有连续状态的数学证明。
- 原生WPF连续注视测试覆盖站立/坐姿、四向与斜向移动、关闭回正、镜像、跨屏标志、拖动标志、专注免打扰、睡眠唤醒；注视没有触发`notice_*`视频，没有增加照顾经验。
- 标准/节能模式均执行连续注视测试。详情为包内`validation432/gaze`、`gaze-eco`的结果、连续参数CSV和实际窗口快照。
- 两轮完整原有动作回归PASS，包含喂食/摸摸队列、预览不刷经验、提醒确认、隐藏恢复和置顶/穿透设置路径。故意注入一次帧解码失败后仍可播放其他动作。日志中的`failed groom`是预期测试注入。
- 实际窗口快照确认猫本体可见、四角透明。左右及上下极限截图的下方40%区域像素一致，头颈区域存在变化；可复现检查见`continuous-verification.json`。
- 查看了注视状态面板、状态卡和设置窗口，没有发现当前视口的文字重叠或截断。

测试使用隔离内存设置/养成对象及独立单实例锁。鼠标坐标注入经过实际窗口像素/DPI适配器，没有移动用户的系统鼠标，也没有修改真实开机启动项或养成数据。

## 性能与限制

最终构建的首张原生猫窗口渲染在本机低于1秒。该数值仅代表本次机器和缓存状态，不是所有Windows环境的启动保证。

空闲采样50.85秒，排除前20秒的启动/转场后：工作集平均160.52 MiB、峰值177.02 MiB，私有内存平均157.50 MiB，CPU为单逻辑核心口径0.53%。不是所有内存指标都低于150MB。

两轮完整动作回归的单核心CPU平均8.43%，工作集平均167.18 MiB。此场景持续播放视频，不是空闲；连续注视混合测试同样包含姿势视频和界面快照，不能将其均值当作纯注视开销。完整逐秒采样与统计在`benchmark432-*.csv/json`。

没有调用强制GC或清空工作集来降低读数。本次没有完成数小时压力、多块物理显示器混合DPI、所有缩放比例或Windows 10实机测试。
