# 4.3.3 注视修复

## 已确认原因

4.3.2 的注视视图只使用 EmissiveMaterial。对保存的真实渲染结果进行数值检查，站立截图的 alpha 最大值为 0，虽然仍有 20,204 个像素带 RGB 颜色。透明窗口不能用这些无覆盖率的像素显示猫。上一轮检查只看了图片预览、四角透明和像素变化，没有检查猫本体的 alpha；其“猫可见”的结论不足，应以本版修复后的检查为准。

另外，ImageBrush.Freeze() 会递归冻结它引用的 BitmapSource。注视曾直接引用视频的 WriteableBitmap，导致恢复视频时 WritePixels 抛出 InvalidOperationException。2026-09-15 的本机错误日志包含该异常。

## 修复范围

- 使用 DiffuseMaterial 和白色 AmbientLight 输出完整 RGBA；不靠叠加一只静态猫遮住错误。
- 注视直接使用常驻站立/坐姿纹理；渲染器遇到外部可写纹理时复制后冻结，保留调用方可写性。
- 视频写入前检查缓冲区是否冻结，必要时重建，作为额外防护。
- 近距离坐标响应增强；横向眼周位移上限从 1.05 调整为 2.1 个源像素，纵向从 0.8 调整为 1.4；头颈变化仍有界，不扩大为全身漂移。
- 保持原动作素材、视频速度、养成和用户数据不变。

## 验收改进

新增渲染测试在修复前报告 56 项失败，修复后通过。它验证站立/坐姿 18 组方向的猫本体不透明度、预乘 alpha 合法性、透明四角和视频缓冲区可写性。真实桌面测试在独立深色/浅色背景窗口前截取桌宠区域，而不是只依赖 PNG 查看器；同时覆盖 60% 用户透明度。方向切换的下方 40% 画面必须逐像素不变。

参数测试和像素测试仍不等于用户观感验收；该模式依旧不是独立眼球动画或真实三维转头。
